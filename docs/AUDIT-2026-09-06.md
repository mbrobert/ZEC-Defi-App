# Internal adversarial audit — wave 1, and the fix round it produced (2026-09-06)

**This is not an external audit.** It is an internal adversarial review of the
Base-first v1 tree at commit `827c5db`, run as four independent lenses, with a
rule that every Medium-or-worse finding had to carry an **executed** proof of
concept — a runnable Foundry test or node script with the command and the
trimmed output — or be recorded as "plausible, not reproduced". The fix round
that followed is commits `9b23864` and `52f4a70`.

Sources: `/tmp/audit2/w1-{A,B,C,D}.md` (the lens reports), `/tmp/fix2/PLAN.md`
(the lead decisions), `/tmp/fix2/done-{CONTRACTS,KEEPER,YIELD,WEB,PROTOTYPES}.md`
(what shipped), `/tmp/fix2/CONTRACT-ABI-DELTA.md` and
`/tmp/fix2/MODEL-NUMBERS-v2.md` (the two hand-off documents). Everything below
was re-checked against the code in this tree, not taken from the reports.

Abbreviations: HF = health factor; LTV = loan-to-value; LT = liquidation
threshold; LP = liquidity provision; MC = Monte Carlo; PoC = proof of concept;
ABI = application binary interface; DoS = denial of service.

The Critical and all ten Highs are fixed. Twenty of the twenty-three Mediums
are fixed or mitigated; three are deferred with reasons (§4). Eighteen of the
twenty-four Lows are fixed; six were deliberately not taken.

**The two findings that mattered most were both silent.** The router's Critical
was a $0.000001 permanent denial of service that no test could see because the
invariant meant to catch it was vacuous. The keeper's two Highs meant the
protection users were shown before signing **had never once run for anybody** —
and the only trace was a log line on a host they cannot see. Neither reverted,
neither errored, neither showed a wrong number. That is the shape to hunt.

## 2 · The seven lead decisions, and why each was made

**D1 — the router's zero-balance assertion becomes a DELTA assertion.**
*Why:* asserting an absolute zero balance on a public address is a permanent
denial of service against every user for the price of one base unit, on an
immutable contract with no rescue. Donations must be inert, not fatal. The
decision explicitly extended to *anywhere else an absolute balance is
asserted*, including the invariant suite, and required a `donate()` action in
the invariant Handler so the class cannot pass unnoticed again. *What shipped:*
snapshot-and-compare per token in every entry point;
`RouterHoldsBalance` → `RouterBalanceChanged`;
`invariant_peripheralsAcquireNothing` + `invariant_donationsDoNotBrickTheProtocol`
with a live `donate` handler action (~11,100 calls per invariant at the raised
settings).

**D2 — no strategy may reach a venue except through a path that enforces the
entry health floor.** *Why:* the fix belonged on the contract side, not the UI.
A floor that lives in one router function is a floor one code path can walk
around, and the shipped hold strategy did. The decision also demanded that the
report state plainly which sequences a user hand-writing calldata can still
build. *What shipped:* `AaveV3Venue.borrow` enforces the floor;
`AaveV3Venue.supply` enforces the registry's offer;
`StrategyRouter.openBorrowOnly` is a first-class entry point so the product
never needs a hand-built batch; `test_FIX_D2d_rawAavePoolCallsRemainTheOwnersRight`
documents the one door that stays open, by name, deliberately.

**D3 — the account's peripheral rights must be opt-in per call, not
automatic.** *Why:* every contract the account called became the active
peripheral with unbudgeted authority, so a raw `exec` to a hostile token — or a
grant on 1 wei of something — escalated to a full drain. *What shipped:*
`Call.callback` default false; `exec` plain, `execWithCallback` opt-in; on the
keeper path the flag comes from `Permission.allowCallback`, so **the owner
decides which target may act back on the account, never the keeper**; depth
bounded at 8. The decision left a choice on the four uncovered token movers —
budget them or refuse them — and **refusal was chosen**: budgeting means four
more calldata decoders in a contract whose whole safety argument is that its
parser and the token read the same number, for a capability no Oilskin flow
uses; `permitTransferFrom` in particular reaches *outside* the account into the
owner's wallet to spend an unspent signature. Refusing fails closed and is
loud; budgeting fails open if any decoder is subtly wrong.

**D4 — the registry owner must not be able to redirect user funds silently.**
*Why:* registering a venue was one owner transaction with no delay, and the
venue the registry named received every calling account's peripheral rights.
*What shipped:* propose → immutable delay → accept, with an event at each step
carrying both addresses and the eta, a `pendingVenue` view, and `enabled()`
checked on every path that follows the registry. **And the honest residual, in
the decision itself:** a timelocked owner is still an owner, so the product
must not claim "no operator custody" — the exact user-facing strings were
listed for the web engineer and every one of them is now changed, the phrases
are in `BANNED_WORDS`, and the prototypes grep for them.

**D5 — the keeper's grant must cover exactly what it plans, and the plan must
fit in one root call.** *Why:* the plan's first call sat outside the only grant
the web asks for, so every protective rung was refused. Since
`StrategyRouter.unwind` already closes ids through the nested path, the plan
should be **one** root call, not two. The same decision fixed `closeMany` /
`claim` deriving the pool from `positionIds[0]` with a reverting lookup: a
keeper rebalance between read and dispatch was killing the whole protective
unwind. *What shipped:* both halves, plus a structural check in the keeper's
`verify-abi` that `GRANT_SELECTORS` contains exactly one entry.

**D6 — staleness must be per feed and real.** *Why:* the live USDC/USD round
was 44,475 s old by the repo's own verified facts against a 10,800 s constant,
so every account read UNKNOWN every tick and the ladder had never run. There is
no single number that works: raising it past a day disables the guard for the
assets that actually move. *What shipped:* each feed's cadence measured from
its own `getRoundData` history, a bound of `max(observed gap) × slack`, the
bounds logged at startup, and — the important half — **a startup self-check
that refuses to run when the policy would make every account UNKNOWN**. A quiet
no-op was the failure mode; a loud fatal is the fix.

**D7 — a protection that cannot be seen is not a protection.** *Why:* the
`warn` rung, and every escalation the keeper had, reached only stdout on a host
the user cannot see; one hung dispatch could starve the fleet for ever; and the
store's write path could corrupt itself into an unstartable state on a full
disk. *What shipped:* a real notify hook for every rung and escalation (log +
webhook, bounded, with delivery failures counted and the `notify` rung only
`NOTIFIED` when a channel accepted); per-dispatch deadlines with quarantine and
rung re-arm; and a write path that checks the bytes actually written and fails
loudly.

## 3 · What the fix round changed, in one place

1. **ABI.** `Call` gained `callback`; `Permission` gained `allowCallback`;
   `exec` became plain with `execWithCallback` as the opt-in;
   `openBorrowOnly`, `execBatchFromFactory`, `MAX_PERIPHERAL_DEPTH`,
   `minOutFor`, `MAX_SLIPPAGE_BPS`, `MAX_BAND_BPS`, `pendingVenue`,
   `proposeVenue` / `acceptVenue` / `cancelVenueChange` and the three

   `claim` takes a band and a deadline and returns `failed`;
   `RouterHoldsBalance` → `RouterBalanceChanged`; `AccountExists`,
   `MixedPools`, `ZeroMinOut` deleted. **266 → 303** entries.
2. **Contracts.** 181 → **244** tests, with the harvested PoCs kept as
   regressions under `test/audit-regressions/` with their attack setups intact.
3. **Keeper.** 139 → **171** tests; its `verify-abi` went from *failing on four

   shape.
4. **Web.** 89 → **125** tests (one of the 89 was red: the ABI seam), plus
   12 Playwright. Every flagged copy string rewritten, a new `operator-powers`

   states including `cannot-act`.
5. **Yield.** 105 → **131** tests; shared 52 → **53**. The gate now prices

6. **Prototypes.** 85/80/45 → **118/109/56** checks, the model short-circuit
   deleted so the pages compute what they publish, and a grep guard against the
   retired custody claims.

## 4 · Deferred, and why

1. **Cross-grant budget aggregation (A-MED-2, first half).** Two grants that
   both list USDC still give the keeper 2× the per-day USDC. Making budgets
   global means an account-level `(token, period)` accumulator that every
   keeper call must read and write — a change to the storage layout, the gas
   profile of every keeper call, and the meaning of `tokenBudgetOf`. That is a
   redesign, not a fix. **Mitigation:** the product issues exactly one grant per
   account, and `CONTRACT-ABI.md` requires any UI that issues a second to show
   the sum.
2. **`revoke` then `grant` still resets the window.** The carry-forward keys
   off a live grant; a revoked one has nothing to carry. Two deliberate owner
   transactions can refill a budget inside a period. Left as is: revocation is
   meant to be a clean break, and the owner is the party being protected.
3. **The budget does not bound a call tree (A-MED-1, deeper half).** Value
   moved by a protocol the tree talks to (an Aave `withdraw`, an engine
   withdrawal) is not charged and cannot be without the account understanding
   every protocol it touches. The half that was a *lie* is closed — unparsable
   movers now fail closed — and `IOilskinAccount`'s doc comment, the ABI
   document and the UI now state the true boundary: **the grant's target, and
   any peripheral it nests into, are trusted code.**
4. **Enumeration's last ambiguity (B-MED-5).** A `Panic(0x32)` at index *k*
   from a cause other than the end of the list is still indistinguishable from
   the end of a *k*-element list. That is a property of the engine's generated
   getter, not of our venue; the fix removed every *other* shape that used to
   be mistaken for the end, and a test asserts the residual explicitly so
   nobody later mistakes it for coverage.
5. **Peripheral-to-peripheral reentrancy (A-LOW-4).** Bounded at depth 8 and
   documented, not prevented. Venue A → B → A is reachable within the bound;
   today's venues are stateless so nothing breaks, and `Peripheral.sol` now
   states that a peripheral with per-call state must carry its own guard.
6. **The six Lens-D lows not taken** (`LT = 0`, nominal vs compounded borrow,
   the 1-ray Aave bound, `width_not_quoted`, the gauge cache TTL and the
   `methodologyUrl` branch). None is a wrong offer. The compounded-borrow one
   is the next to do: it makes the gate 0.1185 pt permissive, in the same
   direction as the defect D-HIGH-1 just closed.
7. **The 8 fork tests remain skipped.** No chain RPC in this container. They
   were updated for the new constructors and the callback opt-in, so they
   compile and will run under `FORK_URL`, but **nothing here was verified
   against live Base state** beyond what `VERIFIED-BASE-FACTS.md` records.
8. **The keeper's notify chain ends at a webhook.** No mailer, no pager, no
   per-user routing. Until something downstream fans it out, "→ keeper notify"
   in the pre-sign copy is a promise the keeper cannot keep alone.
9. **The cbZEC B20 policy read still does not exist.** `web/lib/copy.ts:43`
   claims Oilskin performs an on-chain policy read before touching cbZEC; no
   shipped code does. This was open before wave 1 and is open after it.

## 5 · Residual risk after the fix round

Ranked by what would hurt a user most, and each cross-referenced to the risk
register:

1. **The registry owner is an owner** (`RISKS.md` §16). Instant asset disable,
   instant entry-floor change within (1, 10], and a venue replacement after two
   days that inherits every account's peripheral rights. The delay and the
   events are a warning, not a prohibition — they protect a user only if
   somebody is watching *and* the user transacts inside the window. Nothing on
   chain requires that owner to be a multisig.
2. **No external audit, and no static analysis** (`RISKS.md` §11). Wave 1 was
   internal. 3,492 lines of new on-chain code have never been read by an
   outside party.
3. **The fork suite has never run** (`AUDIT-SCOPE.md`). In particular the
   engine's live end-of-list revert shape is unrecorded, and the venue now
   requires exactly `Panic(0x32)`: if the live shape differs, enumeration fails
   closed — safe, but `positionsOf` stops working until the constant is
   confirmed against the chain.
4. **The trusted-code boundary** (`RISKS.md` §19). Budgets bound direct token
   operations only; the router and the venues it nests into are trusted. That
   is a deliberate, documented boundary, not an oversight — but it is the
   largest remaining surface inside a signed grant.
5. **Keeper delivery stops at a webhook** (`RISKS.md` §10). The protection now
   works; telling the user still does not, end to end.
6. **Untracked collateral means no protection for that user** (`RISKS.md` §10),
   loudly escalated and stored, but still unprotected.
7. **The swap floor is relative to a caller-supplied quote** (`RISKS.md` §13).
   A dishonest quote still gives a bad floor; what changed is that the lie is
   now an explicit, comparable number instead of a silent default of 1.
8. **Both gate models can be wrong together** (`RISKS.md` §21), and the
   emissions anchor's corroboration history is in-process memory, so every
   yield-service restart is a blind window (fail-closed).
9. **The cbZEC B20 disclosure claims a read no code performs** (`RISKS.md` §4).
10. **A grant issued without `allowCallback: true`** looks live and can do
    nothing (`RISKS.md` §10). The product never builds one, the keeper
    escalates it as a configuration error and the dashboard shows `cannot-act`
    — but a grant signed elsewhere is protection that is not there.

## 6 · Process lessons worth keeping

* **An invariant whose Handler cannot reach the forbidden state is
  decoration.** `balanceOf(peripheral) == 0` passed for a thousand runs while a
  one-wei donation would have bricked the protocol for ever. Every invariant
  now has a liveness test behind it.
* **A protection whose failure mode is silence needs a test that asserts it
  fired.** The keeper's two fleet-wide Highs both passed every existing test:
  the code ran, it just never acted. The harvested PoCs are kept as regressions
  *with their attack setups*, expectations flipped, precisely so that "the
  ladder protected this account" is an assertion and not an assumption.
* **Validate a model where the decision is made, not where the data is.** Every
  committed validation row for the closed form sat in deeply-negative cells,
  where its error is smallest. The error at the offer boundary — the only place
  the number changes what a user does — was 7–32 points, and nothing measured
  it.
* **Never let a document be the encoding source.** All four ABI failures at
  hand-off were caught by machine checks against `contracts/out`, not by
  reading. `CONTRACT-ABI.md` is a reading aid and says so on its first line.
